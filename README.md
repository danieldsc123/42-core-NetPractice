# NetPractice

## Description

NetPractice is a 42 networking project consisting of ten simulated network configuration exercises. The goal is to establish bidirectional connectivity by correcting IPv4 addresses, subnet masks, and routing tables while respecting fixed fields. This submission targets login **danda-si**, the supplied NetPractice **1.9** training package, and subject version **6.3**.

The ten `level1.json` through `level10.json` files at the repository root contain the configuration for each level. The project does not require writing a network server or modifying the supplied simulator.

## Instructions

### Run the training interface

Python 3 and a web browser are required. From the repository root:

```sh
# Download net_practice.1.9.tgz from the project page on the 42 Intra first.
# Keep the package locally; the supplied simulator is not redistributed here.
tar -xzf net_practice.1.9.tgz
cd net_practice
bash run.sh
```

Use the local URL printed by the script. Alternatively, from `net_practice/`:

```sh
python3 -m http.server 49242 --bind 127.0.0.1
```

Open `http://localhost:49242`, enter **danda-si** in the training tab, and start. Use a local HTTP server as required by this version of the subject. Stop the server with Ctrl-C.

### Configure and export

Edit only enabled fields. Click **Check again** and confirm that all objectives succeed. Click **Get my config** before moving to the next level and save the resulting `levelN.json`. Each JSON uses the original export structure: `routes` and `ifs`, with values only for editable fields; empty objects for fixed entries are expected.

To reproduce a saved solution, enter the values from its JSON into the corresponding interface and route fields in the matching level, then check and export again. The original interface does not offer a configuration import button. These configurations depend on the login and simulator version.

### Submission

Place **10 exported configuration files, one per level, at the repository root**, alongside this English `README.md`. The local PDF, archive, extracted simulator, and optional verification helper are supporting materials, not replacements for those eleven required files. The 42 materials are excluded from this public repository; download the training package from the Intra to run the interface or verifier. Submit through the project's assigned Git repository.

### Local verification

With Node.js installed and the official training package extracted into `net_practice/`, run from the repository root:

```sh
node tools/verify.cjs
```

This helper reads the ten saved files, checks that they contain exactly the permitted editable fields, regenerates each board for `danda-si`, and calls the unmodified simulator's connectivity checker. It uses a minimal DOM adapter rather than a browser. All **31 objectives across 10 levels** pass, including the simulator's forward and reverse checks. Also reproduce the exercises in the browser to practice for the defense.

## Resources

- Supplied `en.subject.pdf`, version 6.3: requirements and submission rules.
- Supplied `net_practice.1.9.tgz`: training interface, level definitions, original simulator, and export function.
- Supplied evaluation PDF, `Intra Projects NetPractice Edit (1).pdf`: README checks and timed defense. This older scale references package 1.7; the local subject and package use the newer server-based interface.
- [RFC 791 — Internet Protocol](https://www.rfc-editor.org/rfc/rfc791): IPv4 and TCP/IP addressing context.
- [RFC 950 — Internet Standard Subnetting Procedure](https://www.rfc-editor.org/rfc/rfc950): subnet masks and subnetting.
- [RFC 4632 — Classless Inter-domain Routing](https://www.rfc-editor.org/rfc/rfc4632): CIDR prefixes and route aggregation.
- [RFC 1918 — Address Allocation for Private Internets](https://www.rfc-editor.org/rfc/rfc1918): private IPv4 ranges.
- Original simulator source, `net_practice/js/sim.js`: default gateways, routers, switches, route matching, and connectivity behavior within these exercises.

Concepts covered by this project include **TCP/IP addressing, subnet masks, CIDR, network and broadcast addresses, default gateways, routers and switches, routing tables, return paths, public and private addresses, and OSI layers**. In the OSI model, the physical link is layer 1, Ethernet switching is primarily layer 2, IP routing is layer 3, and TCP/UDP operate at layer 4. The exercises focus on IP addressing and routing rather than implementing all layers.

## AI Usage

An AI assistant analyzed the supplied subject, evaluation scale, and training sources; calculated the ten configurations for `danda-si`; executed the original simulator's checks through a Node.js adapter; and drafted this README and the optional verification helpers. The configurations were generated by calling the original `dl_config()` export function with solved field values, then formatted as JSON. The learner must review and understand these solutions, reproduce them independently, and seek peer review before evaluation. The supplied scale requires three random exercises from levels 6–10 within 15 minutes without external resources; a simple calculator is tolerated. Local helpers are for preparation only.
